# PostgreSQL value codec

`PostgresStorage.open(pool, { session, codec })` can transform persisted JSON text without changing the storage contract. With no codec, storage is unchanged.

The asynchronous `encode(address, json)` and `decode(address, json)` methods receive the schema, session, table, and record ID independently of the stored value. Document revisions also receive their commit sequence. Both methods must return valid JSON text. Tasks and submissions can be updated at the same address: never derive an encryption nonce solely from the address. The schema is a physical location; codecs that authenticate it must define an explicit restore/rename policy. A codec can use this address as authenticated encryption context; it must distinguish its ciphertext from legacy data without silently treating corrupt ciphertext as plaintext.

The hook covers entry, task, and submission records and document revision contents (both bases and deltas). It does not transform conversation records, document metadata, or indexed columns. Those remain available to SQL for ancestry, scheduling, and document lookup. Do not put confidential content in metadata fields that are outside the codec.

Document contents are decoded before applying deltas or copying a document. The copied base is encoded under the destination document's identity. A read that overlaps a commit does not install stale mutable cache state; immutable entry records remain cacheable. Read-through caches and commit absorption retain normal values in memory; the codec is an at-rest boundary, not protection against a process authorized to read the session.

Encoding failure refuses the batch without writing an unencoded replacement; previously committed batches retain their normal partial-commit semantics. Decoding failure rejects the read. Provide bounded retries and deadlines in codecs that depend on an external key service. The harness treats failed commits as storage failures, so validate application payload limits before committing.

Deploy compatible readers before enabling a codec's encrypted writes. Keep the decoder installed after switching writes off. A JSON-string envelope is distinct from legacy object records and object/array revision contents; no-codec readers reject that shape. Revision contents are JSON values re-serialized on read, so a codec must not depend on preserving their original whitespace. Storage does not provide key management, automatic backfill, retention, or ciphertext rotation; the application owns these policies and must use the same address format in any maintenance or cross-session copy paths.
